# 00 · 未随仓发布的内部件清单（对外读者先读这份）

> 性质：**公开仓的「未发布清单」**（manifest）。
> 背景：本仓把「内部资产不入公开树」当作红线执行。于是**一批只给维护者/agent 用的过程文件、
> 审计、蓝图、台账、法务材料不随仓发布**。而一些**已经入库的文档**里，仍引用着这些没发布的内部件——
> 对本地维护者是活引用，对外部读者就是**死链**。
> 这份清单的作用：**预先说清「哪些引用点指向了没随仓发布的内部件」**，让你点开前就知道
> 它会 404、为什么 404、以及该看什么替代物，而不是撞上沉默的 404。
>
> 这是一项**观感问题，不阻断使用**：代码侧的交付判据（冷启 / 账本 / 自证）都自洽，
> 死链只影响「第一次翻 docs」的第一印象。

---

## 三桶分类（2026-11-09，78 条命中的真实构成）

### A 类 · 真缺口：引用了「没随仓发布的内部件」（外部人点开会 404）

**红线说明**：这些不是「丢失」，是**刻意不发布**。它们承载的是维护者判断、审计取证、商业与法务
决策，属于内部资产。公开仓只发「外部读者需要且能验证」的那部分（见下一节）。

### B 类 · 启发式误报（不是坏链接，是代码片段里的 token 被当路径）

`drift-check` 用启发式从 markdown 里抽「像路径」的片段，会误伤这些：

- `res.json`、`result.json`、`routing-mode.json`、`shell.js`、`shell.css`、`lib/redact.demo.js`
  等——是**正文/代码示例里的变量名或函数调用**（如 `res.json()`、`res.json`），不是指向某个文件。
- `settings.json` / `opencode.json` / `config.yaml` / `cordis.yml` / `.dsh/profiles/desktop/cordis.patch.yml`
  是**「你自己要建的配置/部署文件」的示例**（文档在教你创建它们），不是指向仓内已存在的文件。

这一类**不是问题**：它们是文档在演示「你该填什么 / 该建什么」，本就不该指向仓内文件。
`drift-check` 目前对它们也会报警——这是**已知误报**，后续会收窄启发式；在此先如实登记，
**不要为消除它去删正文里的示例代码**。

### C 类 · 外部/构建产物路径（本就不属于本仓）

- `deepseekharness.io/python-sdk/`、`@deepseek-ai/dsh-client-ui-primitives/...` —— 第三方包/站点路径。
- `dist/server/handlers/chatHandler.js` —— 构建产物路径（dist 不入库，见 §Docker 一节）。
- `dsh-context/src/client/categories.ts` —— 外部 harness 侧代码路径。

这些指向的是**本仓之外的东西**，对阅读本仓文档不构成「点了 404 还找不到」的问题。

## 那「发布了什么」？（外部读者该看的入口）

对外读者需要的、**已入库且能自验**的材料都在这些入口，从这里进不会撞死链：

- **`README.md`** —— 一条命令冷启、看到第一笔真实账单（主入口）。
- **`docs/00-codebase-map.md`** —— 仓库结构地图。
- **`docs/01-feature-matrix.md`** —— 功能矩阵（替代 10-initiatives 的产品/调研）。
- **`docs/03-architecture/**`** —— 架构与外部 harness 接入约束（替代 L2-BLUEPRINT）。
- **`docs/04-tech/**`** —— 路由引擎规格、脱敏、安全白皮书（替代 02-product 的行动清单，看设计稿）。
- **`docs/07-ops/**`**（runbook / rollback / ENV-NOTES）—— 运维与回滚（替代 P0-FIXES 台账）。
- **`docs/08-user/faq.md`** —— 用户 FAQ（替代 04-business 商业化细节）。
- **`docs/CHANGE-MAP.md`** —— 变更台账（替代 QUEUE / 过程文档）。
- **`scripts/verify.sh`** —— 只读自检脚本，外人不看界面也能验（交付判据 III）。

## 处置口径（与维护者同步）

- **本次采取 option (b)**：以上清单（本文件）即「未随仓发布文档清单」，公开可查、加法式、
  不改动任何已入库文档的语义（风险最高、无法在此环境完整验证的那一步不做）。
- **未采用的 option (a)**（给每处内部引用加「（内部文档）」标记 + 让 drift-check 跳过带标记的）：
  它是「最终更对」的形态，但要跨 15+ 份文档机械改写，有损文档语义的风险，留到有余力时再做。
- **B 类误报**：后续收窄 `drift-check` 启发式（代码片段里的 `x.json`/`x.js` 不当路径），
  在那之前以本清单为准，**不要为消除误报删正文示例**。
- **复现**：`node scripts/drift-check.js --scan 'docs/**/*.md'`（见上）。
