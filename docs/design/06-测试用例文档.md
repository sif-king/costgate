## 0. 验收纪律（最高优先级，违反即作废）

> **`jest` 全绿 ≠ 验收通过。** 这是上一轮已被老板驳回的方法论错误（`UI现状取证报告` 第 0 节）。
> 理由：前端 jest 仅断言 HTML **字符串**含某段字符（如 `dashboard.test.js`），测不出：
> - 主题是否真联动（computed style 不变）
> - 图标是否压字、栅格是否错位
> - 导航是否死胡同、按钮是否真点击有反应
> - 残留测试数据 / 占位文本

**本仓 UI 验收的唯一通过条件**：在隔离实例 `PORT=18801`（puppeteer-core + 系统 Chrome，参照 `UI现状取证报告 §1`）逐条跑真实浏览器用例，截图 + 交互冒烟，对照本文逐条判定。**jest 只作为回归守门，不作为交付判据。**

## 4. 验收流程（每次交付必走）

1. 起隔离实例：`HOME=/tmp/mp-test-home PORT=18801 MP_CONSENT_BYPASS=1 node server.js`。
2. 跑 `npm test`（jest 守门，仅判回归）。
3. 跑 `npm run e2e`（playwright）：逐页截图 light/dark + 交互冒烟。
4. 对照本文 §2 全局门 + §3 用例逐条判定，**全绿（含 E2E）才可声称完成**。
5. 未过项**列出具体 file:line + 截图**，禁止以"jest 绿"搪塞。
