> 角色视角：**架构师 / 开发负责人**。对齐 `01/02/03/04`。本文把设计落地为可执行的工程方案与排期。
> 基线：`docs/09-review/UI现状取证报告-2026-10-23.md`。

## 0. 核心约束（来自方法论纠错）

1. **jest 绿 ≠ 验收**。前端测试只断言字符串（`dashboard.test.js` 等），测不出主题联动/图标压字/死导航。UI 验收以 `06-测试用例文档.md` 的真实浏览器用例为准（`UI现状取证报告` 第 0 节）。
2. **不重写后端**。本次只动 `multi-proxy-manager/public/` 前端 + 极少量 server 静态路由；不改 9 代理转发逻辑、不改 `process-manager.js` 的代理定义（已正确返回 9 个）。
3. **隔离验收保留**。沿用 `HOME=/tmp/mp-test-home PORT=18801 MP_CONSENT_BYPASS=1` 的 puppeteer-core + 系统 Chrome 链路，生产 18792 不动。

## 2. 目标架构（前端）

```
multi-proxy-manager/public/
  tokens.css            ← 唯一色板来源（保留，已 AA 合规）
  components.css        ← 组件实现（按 04 §5 补全态）
  shell.js              ← 【新增】统一外壳：主题 init + 侧栏注入 + 导航/路由 + 焦点管理
  icons.js              ← 【新增】12 图标内联 SVG 字符串（04 §6.2），供 shell 与各页复用
  shell.css             ← 【新增】侧栏/顶栏/栅格布局（取代散落的 layout 样式）
  dashboard.html        ← 引用 shell.js + shell.css，删内联 nav
  floor.html / context.html / knowledge.html / skills.html / sessions.html / logs.html / proxy-config.html / settings.html / legal.html
                        ← 全部改为引用 shell.js + shell.css + tokens.css + components.css（统一 4 文件 head，删 colors_and_type.css）
  consent.html / login.html ← 不进导航（保留，但 login 后跳 dashboard）
```

### 2.1 `shell.js` 职责（一次性解决 P0-1/P0-2/P0-3/P0-4/P0-5）
- **主题 init**：首屏（在 `<head>` 内联小段）读 `localStorage.theme`(默认 auto)，设 `<html data-theme>`；auto 时 `matchMedia` 监听系统切换（`04 §7`）。**必须挂在 `<html>`，纠正 `settings.html:13` 的 `body` 误用。**
- **侧栏注入**：所有页面挂载相同 10 项侧栏 + 底部法务链接（纠正 1/13 + 死胡同）。激活态按当前 `location.pathname` 匹配。
- **顶栏注入**：标题（按路由）+ 主题三态切换器（与设置页同步）。
- **统一栅格容器**：内容区 `max-width:1200px` + `grid` 工具类（纠正 floor 200px / dashboard 2/3）。
- **品牌名**：侧栏顶部统一 `Multi-Proxy Manager`。

### 2.2 数据同源（解决 P0-8）
- dashboard 与 proxy-config 都从同一 API（如 `/api/proxies` 或 `process-manager.buildProxyConfigs()` 的序列化）读取 9 个代理。当前 proxy-config 显示 3 个是其独立硬编码列表 → 改为 `<ul id="pxList">` + `shell.js` 拉取同一数据源渲染（参照原型 `prototype/index.html` 的 `renderList`）。
- 冲突三态 `occupied/free/unknown` 用 `agent-owner.js` 的结果（已实现三态，见 `01/03`），在卡片上以徽标呈现。

### 2.3 图标统一（解决 P0-6）
- 删除所有 `+ ◇ ○` 字符占位、emoji；改用 `icons.js` 的 12 个内联 SVG（`04 §6.2`），`aria-hidden` + 文本/`aria-label`。

## 3. 实施阶段（每阶段结束都要真实浏览器验收，禁止只跑 jest）

### Phase A0 — 解耦 design-system 测试（**前置，否则 Phase A 会砸测试**，已核实）
> 交叉评审发现：`tests/unit/frontend/design-system.test.js` 同时做了两件事：
> ① 钉对比度（第 498-568 行，覆盖新旧两套色板，正确、保留）；
> ② **强制每页 `toContain('colors_and_type.css')`**（第 478-486 行，仅豁免 index/login/consent/legal）+ 钉旧色板 `--color-*` 的 hex 与类名（第 68-216 行）。
> 而本方案的 Phase A 要"删除 `colors_and_type.css` 引用"。两者直接冲突——若先删引用，该测试必红。
> 因此 **Phase A 之前必须先改测试**：
> 1. 删除第 478-496 行 `All Pages Share CSS` 里对 `colors_and_type.css` 的 `toContain` 强制要求（改为校验 `tokens.css` 引用，且把 legal/context 纳入校验，消除 G-05/G-06 缺口）。
> 2. 删除第 68-216 行 `CSS Variable Definitions` / `Dark Mode CSS Variables` 对**旧色板** `--color-*` 的 hex 与类名断言（保留第 498-568 行的对比度钉死，这是真护栏）。
> 3. 跑 `npm test` 确认仅剩对比度用例全绿后再进 Phase A。
> 注意：`04 §9` 原话"已钉对比度（不钉 hex）"不严谨——该文件**确实还钉了旧色板 hex**，本段为更正。

### Phase A — 接线与统一外壳（P0-1/P0-2/P0-3/P0-4/P0-5）
1. 新建 `shell.js` / `icons.js` / `shell.css`。
2. 13 个页面 head 统一为 `tokens.css + components.css + shell.css`，删除 `colors_and_type.css` 引用；`legal.html` 补 CSS；`context.html` 补缺失 2 个。
3. 所有页面 `<body>` 起 `<div id="app-shell">` 由 `shell.js` 渲染侧栏+顶栏+内容槽。
4. 品牌名统一为 `Multi-Proxy Manager`（搜 `Proxy Manager` 替换）。
5. 栅格统一（KPI `auto-fill minmax(280px,1fr)`，主区 12 列或两栏 `1.4fr 1fr`）。
- **验收**：11/11 页 `themeLinked=true`（切 `prefers-color-scheme` 生效）；导航项统一 10；settings/legal 可达可退。

### Phase B — 数据同源与代理卡（P0-8 + 冲突三态）
1. dashboard + proxy-config 同拉 `/api/proxies`，渲染 9 卡。
2. 冲突三态可视化（occupied/free/unknown）。
3. 启动/停止按钮接真 API（先逐一点击取证，确认非死按钮；`01 §7(F)` 的 5 个无落地 BUTTON 须裁决）。
- **验收**：两页代理数一致=9；unknown 有解释文案；点启动后状态回写。

### Phase C — 状态完整性（P0-9 空页 / 错误态）
1. sessions/knowledge/skills/context 等无数据页补诚实空态（非留白）。
2. 所有数据请求补错误态（图标+原因+重试）。
3. 加载态骨架（尊重 `prefers-reduced-motion`）。
- **验收**：每页非空骨架/空态/错误态三态可演示；无裸白页。

### Phase D — 图标与细节收口（P0-6 + a11y）
1. 全站字符占位/emoji 替换为 SVG。
2. 焦点环、aria、键盘可达全量补（04 §5/§8）。
- **验收**：Tab 遍历无死焦点；图标均有可访问名或 `aria-hidden`+文本。

## 4. 开发规范
- 组件只允许引用 `tokens.css` 变量，禁止散落 hex（lint 可用 `design-system.test.js` 钉对比度）。
- 任何新页必须 `<script src="shell.js">`，否则 CI 门禁拦截（新增 `tests/e2e` 检查 nav 项数=10）。
- 提交前必须：① `npm test`（jest，仍跑）② 真实浏览器 E2E 截图对比（新增 `tests/e2e` playwright 或复用 puppeteer 脚本，**先 `npm i -D playwright` 下载浏览器**，消除 `UI现状取证报告 P0-1` 指出的"浏览器未下载"缺口）。

## 5. 风险
- desktop Electron 壳 splash/主题：沙箱不可验 GUI，需在真机（Mac）人工冒烟（归 `T15` desktop 冒烟）。
- `index.html` 与 `dashboard.html` 合并（`01 §7(D)`）：合并时确认 login 后跳转目标、SEO/书签不受影响。
- 旧 `colors_and_type.css` 被 `design-system.test.js` 读取作别名桥（见 `settings.html:7` 注释）：删除前先确认测试改完，避免回归。
